# PLDBS pipeline at 250 Hz

This ports the Simulink model from Guo et al. 2025 (*Brain Stimulation* 18:1705) from 4096 Hz to
**250 Hz**, the sampling rate of implants such as the Percept. It compares the result with the
4096 Hz baseline in `../analysis`. All numbers are in
[`results/summary_250_vs_4096.md`](results/summary_250_vs_4096.md) and
[`results/port250_comparison.png`](results/port250_comparison.png); both are generated by scripts.

## How to run
```
cd analysis250
matlab -batch "run_port250"     % builds every model variant, runs every sweep, writes the summary (~30 min)
```
- `build_model(fs, opts)` loads the original `SimulnkModel/Estimationdataset1.slx`, changes everything that depends on the sampling rate, and saves a **new** model `SimulnkModel/Estimationdataset1_fs<fs>[_variant].slx` plus `dataset1_fs<fs>_<aa>.mat`.
  - The original file is never modified.
  - Generated models and data are git-ignored and can be rebuilt with this function.
- Options:
  - `trigger`: `original`, `nearest` or `predict`
  - `aa`: `causal` or `ideal`
  - `artifact`: `on` or `off`
- The simulation and evaluation code is shared with `../analysis`:
  - `run_baseline` and `sweep_phases` take a `cfg` argument with the model, data file and sampling rate.
  - `eval_phase` always takes the zero-phase ("true") phase from the original 4096 Hz recording, at each pulse's actual time.

## What changes at 250 Hz
All of these were found by inspecting the model; `build_model.m` lists them.

| Item | 4096 Hz (shipped) | 250 Hz |
|---|---|---|
| Solver step, sample times | 1/4096 | 1/250 |
| NRO integrator step `del` (×2) | 1/4096 | 1/250. ω0 = 5ν = 110 Hz < Nyquist; it stays stable |
| Kalman AR(2) | [1.99798, −0.99964] | [1.56768, −0.99405]: poles mapped z → z^(4096/250), so the continuous-time model is unchanged |
| Bandpass | **cheby1, order 10, passband 18–24 Hz, 1 dB ripple** (identified exactly from the gain blocks; not the 4th-order filter in `Beta_2CycleByCycle_30s.m`) | Same spec redesigned at 250 Hz. Group delay is ~240 ms at 21 Hz |
| Artifact templates | 42 samples (~10 ms) | Causal 4th-order Butterworth 100 Hz anti-alias filter, then decimation: **9 samples, ringing for ~7 samples (28 ms)** |
| Template Selector rows | 1:42 | 1:9 |
| Zero-crossing / SSPE `fs` | 4096 | 250 |
| arHT | buffer 500, order 24, Hilbert 128, edge 64 | Re-tuned in time units: 64 / 8 / 32 / 8 samples |
| Trigger | fires when \|φ − target\| < 0.02 rad | `nearest`: fires on the sample nearest the target. `predict`: aims one sample early |

**Validation gate:** `build_model(4096)` reproduces the shipped model exactly. Bandpass coefficients match to 1e-13, and the 8-target sweep gives identical pulse counts, bias, std and accuracy.

## Findings (NRO, 8 target phases; see the summary for every condition)
1. **The shipped trigger rule fails at 250 Hz.** One sample advances ~32° at 22 Hz, so the ±0.02 rad window is usually stepped over: 1.5 pulses/s instead of ~21.
2. **The sampling rate alone costs almost nothing once the trigger is fixed.**
   - Without the artifact, the `predict` rule at 250 Hz gives bias 1.8°, std 23.0° and 94.6% within ±45°.
   - At 4096 Hz the same measures are 0.7°, 22.8° and 94.2%.
   - Without the one-sample lead (`nearest`), a constant ~30° lag appears. It comes from the model's one-sample delay between trigger decision and stimulation (`Pulse generator2/Delay5`), which is 2° at 4096 Hz but 32° at 250 Hz. A real device has the same kind of decision-to-stimulation latency and needs the same compensation.
3. **The stimulation artifact is the main problem at 250 Hz.**
   - After anti-alias filtering, each pulse rings for ~28 ms, more than half of a 45 ms beta cycle.
   - The paper's 12 ms Kalman window leaves so much residue that the loop locks onto its own artifacts: 444% beta error and std 150°.
   - With the window widened to 28–32 ms, the Kalman filter keeps the error to 17–20%. Blanking+interpolation, sample-hold and zeroing reach 37–64% at the same window, a wider margin than at 4096 Hz, where all methods stay within 2–9%.
   - Even so, phase locking drops to **70% within ±45° (std 49°)**, compared with 94% at 4096 Hz.
4. **An ideal zero-phase anti-alias filter is worse** (std 71°). It spreads the artifact into the samples *before* the trigger, where the Kalman window does not reach. It is also not realisable in a device.
5. **The bandpass-delay caveat from the 4096 Hz baseline still holds.**
   - Against the true zero-phase phase, delivered pulses are at chance (≈40–50% within ±90°) at both rates.
   - The redesigned bandpass has ~240 ms of group delay at 250 Hz.
   - The sampling rate is therefore not what limits true-phase targeting; the narrow bandpass is.

## Limitations
- The artifact is simulated as the 4096 Hz recorded templates (TMSi amplifier, monopolar stimulation) passed through an assumed 100 Hz anti-alias filter. Real implant front ends are different: they are built for sensing during stimulation, use symmetric referencing, and handle artifacts in hardware. The 28 ms ringing and the artifact amplitude are specific to this assumption.
- The data are one 60 s STN recording, and the evaluation is simulation only, as in the paper's comparison.
- Still open (optional plan step 6): a low-delay bandpass variant, to test whether the 250 Hz pipeline can lock to the *true* phase. It needs a structural change to the filter blocks, because the shipped 5-biquad structure fixes the order at 10.
